## Антипаттерны ООП (развёрнуто)

**God object** — один класс знает про конфиг, сеть, БД, UI, отчёты. Симптом: файл на 3000 строк, любой баг «где-то там». Лечение: SRP, выделение типов, тонкий `main`.

**Singleton как глобальное состояние** — `getInstance()` для всего. Скрытые зависимости, сложные тесты, гонки на lazy init. В C++ предпочитай передать зависимость в конструктор (DIP). Singleton уместен редко (логгер с чёткой политикой).

**Наследование ради reuse** — `class MyList : std::list<T>`. Ломает инварианты STL, клиент вызывает лишнее. Композиция: поле `list<T>`.

**Anemic domain model** — классы только с геттерами/сеттерами, вся логика в «сервисах». Инкапсуляция пустая. Лучше: поведение рядом с данными, где уместно.

**Base class knows too much** — fragile base class: изменение protected hook ломает всех derived. Предпочитай композицию или маленькие интерфейсы.

**Забытый virtual destructor** — UB при `delete` через base*. Выучи правило из главы 5.

**Slicing** — передача polymorphic type by value. Исправление: const& / pointer / unique_ptr.

**«Interface for everything»** — десять virtual классов на учебник; SOLID-театр без второго реального use case.

**Copyable ThreadPool / Queue** — нарушение и RAII, и SRP; move-only или unique ownership.

## Чеклист перед code review (своего кода)

1. Полиморфный delete — virtual ~Base?
2. Инвариант — только через public API?
3. Новая фича — новый тип или правка giant switch?
4. Подтип — можно ли подставить без dynamic_cast?
5. Зависимость — `new Concrete` внутри сервиса или в `main`?

## SOLID — одна страница повторения

- **S:** одна причина для изменения; пул ≠ очередь ≠ стадия.
- **O:** новое поведение — новый тип/лямбда/шаблон, не switch в центре.
- **L:** подтип не ломает контракт базы; Square/Rectangle — антипример.
- **I:** узкие интерфейсы; не заставляй реализовывать лишнее.
- **D:** политика зависит от абстракции; SQLite в `main`, не в сервисе.

## Мифы, которые том 8 развенчивает

**«ООП = классы везде»** — namespace + free functions + templates — нормальная доля C++ проекта.

**«SOLID = enterprise только»** — принципы масштабируются вниз: даже три класса в учебном mini-DIP проще тестировать.

**«Наследование устарело»** — устарело **неправильное** is-a; композиция preferred, не запрет наследования.

**«Virtual медленный — не использовать»** — на границе I/O и UI virtual negligible; в hot inner loop — template (OCP другим путём).

**«Я прочитал — значит умею»** — без 2–4 недель практики из плана выше том остаётся теорией. Вернись к вопросам самопроверки **всех** 14 глав через месяц.

## Если забыл термин (микро-глоссарий)

- **Инвариант** — правило, всегда true для валидного объекта между вызовами API.
- **Slicing** — копирование derived в base value, потеря части объекта.
- **RAII** — ресурс живёт в scope объекта-владельца.
- **Composition root** — место сборки графа зависимостей (`main`).
- **Substitutability** — подтип не ломает ожидания кода под базовый тип.
