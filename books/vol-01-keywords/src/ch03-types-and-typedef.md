# Глава 3. Типы, enum, using

## Зачем эта тема

Пока ты объявляешь `int n`, язык использует встроенные имена типов. Как только появляется «заказ», «сокет», «цвет кнопки», тебе нужен **свой** тип — и грамматика открывает keywords `class`, `struct`, `union`, `enum`. Параллельно возникает задача назвать длинный тип короче: `typedef` из C и `using` из современного C++.

Ошибки на этом уровне дорогие, потому что их не ловит один прогон теста: неявное преобразование старого `enum` в `int` портит перегрузки; `class Derived : Base` без `public` ломает ожидания полиморфизма; неправильный `union` с нетривиальным членом даёт UB без санитайзера. Том 8 поговорит про проектирование классов; здесь мы читаем **keywords**, которые компилятор видит в объявлении.

## `class` — не только «объектно-ориентированность»

Слово `class` в C++ означает начало определения **class type**. Внутри могут быть данные, функции, вложенные типы, друзья. По умолчанию члены **private**: внешний код не трогает поля, пока ты не открыл секцию `public`.

```cpp
class Order {
    int id_;
    std::string sku_;
public:
    explicit Order(int id, std::string sku)
        : id_(id), sku_(std::move(sku)) {}
    int id() const { return id_; }
};
```

Keywords **`public`**, **`protected`**, **`private`** — не «модификаторы полей» в смысле Java, а **спецификаторы доступа** в грамматике. Они действуют до следующей секции. Можно чередовать `public:` и `private:` сколько угодно; порядок не регламентирован стилем Google или LLVM — важна читаемость для команды.

`protected` нужен в иерархиях: производный класс видит protected базы, чужой код — нет. Если иерархии нет, `protected` встречается редко, но keyword остаётся частью языка.

Имя класса вводит **область имён** для вложенных имён и для квалификации снаружи: `Order::id()` в определении метода. Keyword **`this`** (глава 5) внутри метода указывает на текущий объект.

### Наследование и keyword `class` во второй роли

Когда пишешь `class Derived : Base`, по умолчанию наследование **private**: снаружи `Derived` не IS-A `Base` для обычного кода. Публичный полиморфизм почти всегда оформляют `class Derived : public Base`. Разница между `struct` и `class` при наследовании — та же логика defaults, что и для членов (см. ниже).

## `struct` — тот же механизм, другие умолчания

В C++ нет отдельного «C-struct без методов». `struct` вводит тот же class type, что и `class`, но члены по умолчанию **public**, а наследование по умолчанию **public**.

```cpp
struct Vec2 {
    double x = 0.0;
    double y = 0.0;
};
```

Такой тип можно передать в функцию, копировать, задать конструктор — keyword `struct` этому не мешает. Стиль «данные без инвариантов — struct, инварианты и скрытое состояние — class» не записан в стандарте, но помогает читателям. В заголовках STL много `struct` с методами и конструкторами.

Сравнение defaults стоит запомнить один раз:

| | `struct` | `class` |
|---|----------|---------|
| Члены по умолчанию | public | private |
| Наследование по умолчанию | public | private |

## `union` — одна память, строгие правила жизни

`union` объединяет несколько полей в **один адрес**. Размер — с учётом выравнивания, обычно как у самого большого члена. Это экономит память в протоколах и драйверах, но язык с C++11 ужесточил правила: в каждый момент «активен» определённый член; читать другой — нарушение, если не было явного переключения по правилам стандарта.

```cpp
union Word {
    std::uint32_t u;
    std::uint8_t b[4];
};
```

Если в `union` положить тип с нетривиальным конструктором (`std::string`), жизненный цикл нужно вести вручную (placement new, явный деструктор активного члена). В учебном и прикладном коде на Linux чаще берут **`std::variant`** **(C++17)** — тот же смысл «одно из нескольких», но типобезопаснее. Keyword `union` остаётся в языке для низкого уровня и совместимости с C.

## Перечисления: `enum` и `enum class`

Старое **unscoped** перечисление:

```cpp
enum Status { Ok, Warn, Fail };
```

Имена `Ok`, `Warn` попадают в окружающую область видимости. Старый код неявно приводил перечисления к целым — отсюда баги в `switch` и перегрузках.

**Scoped enumeration** **(C++11)** — keywords `class` или `struct` сразу после `enum`:

```cpp
enum class Status { Ok, Warn, Fail };
Status s = Status::Ok;
```

Значения не смешиваются с `int` без `static_cast`. Для API и state machine это почти всегда лучший выбор. Underlying type задаётся явно: `enum class Code : std::uint8_t { ... };` — полезно для сетевых пакетов и компактного хранения.

Keyword `enum` один; различие задаётся наличием `class`/`struct` после него. `enum struct` допустим, но редок — читается как `enum class`.

## `typedef` и эволюция к `using`

`typedef` создаёт **псевдоним типа**:

```cpp
typedef unsigned long ulong;
typedef std::vector<int> IntVec;
```

Синтаксис читается справа налево: «`IntVec` — это vector of int». Для указателя на функцию головная боль:

```cpp
typedef void (*Handler)(int);
```

С **C++11** тот же смысл яснее с **`using`**:

```cpp
using ulong = unsigned long;
using Handler = void(int);
```

Для шаблонов разница критична. Alias template:

```cpp
template<typename T>
using Vec = std::vector<T>;
```

`typedef` **не может** параметризовать `T` в таком виде. Поэтому в новом коде предпочитают `using`; `typedef` остаётся в легаси и в системных заголовках.

Внутри шаблона, если псевдоним зависит от `T::something`, понадобится keyword `typename` — глава 10.

## Анонимные типы и `enum`

```cpp
enum { MaxSlots = 16 };
```

Анонимное перечисление вводит константы в scope. Анонимный `struct` внутри функции иногда используют для локальных агрегатов; для публичного API лучше именованные типы — иначе документация и отладка страдают.

## Сценарий: как keywords складываются в маленьком API

Представь тип заказа для учебного `forge-cli` из трека cicd — не готовый код, а мысленный эксперимент. Ты хочешь статус «в очереди / в работе / готово» и идентификатор, который нельзя путать с обычным `int`.

Разумный выбор сегодня — `enum class Status : std::uint8_t` и `class Order` с закрытыми полями. Снаружи видят только методы; keyword `class` здесь не «включить ООП», а зафиксировать **private по умолчанию**. Если бы ты написал `struct Order` с публичными полями, тот же компилятор собрал бы программу, но контракт «инвариант внутри» слабее — это стиль и команда, не ошибка компилятора.

Для логов иногда хотят короткое имя типа очереди: `using OrderQueue = std::deque<Order>;` в заголовке. Это alias, не новый тип: `OrderQueue` и `std::deque<Order>` для overload resolution одно и то же. Если позже очередь станет шаблоном политики, alias template на `using` спасёт от копипасты `typedef` по всему репо.

Такой сценарий связывает главу 3 с тем, что ты уже делаешь в упражнениях: там редко пишут `enum class` в каждом файле, но в промышленном API keywords из этой главы — ежедневная гигиена.

## Типичные ошибки

Писать API на unscoped `enum` и удивляться конфликту имён `Red` в двух перечислениях. Думать, что `struct` нельзя наследовать или запрещать методы. Класть `std::string` в `union` «как в C». Использовать `typedef` там, где нужен alias template.

## Краткое резюме

`class` и `struct` — один вид типа, разные defaults. `public`/`protected`/`private` оформляют доступ. `union` — общая память, осторожно с lifetime; в приложениях чаще `variant`. `enum class` — современный enum. `using` предпочтительнее `typedef`, особенно в шаблонах.
