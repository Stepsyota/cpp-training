# Глава 5. Указатели и ссылки

## Зачем эта тема

В объявлениях C++ символы `*`, `&` и `&&` задают **указатели** (pointer — хранит адрес) и **ссылки** (reference — альтернативное имя объекта). Отдельных keywords для «pointer» нет, но keyword **`nullptr`** **(C++11)** заменил опасные макросы для нулевого указателя, а keyword **`this`** — указатель на текущий объект в методе класса.

Без этой главы не читаются сигнатуры `std::thread`, `emplace_back`, move-семантика и половина STL. Ты уже передавал лямбды с `[&]` и `[this]` в кузнице: там важно понимать, что ссылка — не «маленький указатель для красоты», а контракт на время жизни объекта. На Fedora GCC и Clang разбирают одни и те же правила; отличия чаще в диагностике dangling reference, чем в семантике.

## Указатель и оператор `*`

Указатель — объект, который хранит адрес другого объекта или **null** (нулевой адрес). Его можно **переназначить** на другой адрес:

```cpp
int n = 42;
int* p = &n;
*p = 1;
```

В **выражении** унарный `&` — **address-of** (взять адрес), unary `*` — **dereference** (разыменование). В **объявлении** `int* p` звёздочка — часть типа «указатель на int». Контекст решает, keyword ли это или punctuator — путаница новичков номер один.

Сценарий «опционально есть значение»: указатель может быть `nullptr`; вызывающий обязан проверить или договориться, что функция не разыменовывает null. Ссылка для «всегда есть объект» — ниже.

## `nullptr` (C++11)

Keyword **`nullptr`** — нулевой указатель для любого pointer type и для `nullptr_t`:

```cpp
int* p = nullptr;
void f(int*);
void f(int);   // overload
f(nullptr);    // выберет указатель, не int
```

Макрос **`NULL`** из C часто разворачивается в `0` или `((void*)0)` и ломает overload resolution. Литерал `0` в новом коде для указателей не используют. **(C++23)** появились уточнения вокруг `std::nullptr_t` в generic code; для повседневного кода достаточно `nullptr`.

## lvalue reference `&`

**Lvalue reference** — второе имя уже существующего объекта:

```cpp
int n = 0;
int& r = n;
r = 5;   // меняется n
```

Ссылку **нельзя** оставить неинициализированной: `int& r;` — ошибка. После привязки нельзя «пересадить» ссылку на другой объект — в отличие от указателя. В API «гарантированно живой объект с известным владельцем» часто берут `T&`.

### const lvalue reference

**`const T&`** принимает и lvalue, и rvalue (временный объект):

```cpp
const int& cr = 42;
```

Для temporary компилятор может **продлить lifetime** (продление жизни временного), чтобы ссылка была валидна до конца области видимости ссылки — но правила с return type и member references коварны; возвращать `const T&` на локальную переменную нельзя.

В range-for `for (const auto& x : vec)` ты избегаешь копий элементов `vector<T>` — стык с главой 2 про `auto`.

## rvalue reference `&&` (C++11)

**Rvalue reference** привязывается к **rvalue** — временным объектам и результатам `std::move`:

```cpp
void take(std::string&& s) {
    // тело: s — lvalue с именем, хотя тип параметра был rvalue ref
}
```

Параметр `T&&` позволяет «украсть» ресурс у временной строки вместо копирования. Внутри функции имя `s` — **lvalue**, поэтому передать дальше как rvalue нужно **`std::move(s)`** — не keyword, функция из `<utility>`.

### Reference collapsing (сжатие ссылок)

В шаблонах комбинации `T&`, `T&&` сжимаются по таблице стандарта: например, `T& &` → `T&`, `T&& &&` → `T&&`. Отсюда **`std::forward`** и perfect forwarding в томе 2. Keywords `&` и `&&` в типе — не «два амперсанда для красоты», а часть deduction.

## Value categories — коротко (C++11)

**Lvalue** — имеет адрес, обычно имя переменной. **Rvalue** — временное, «готовое отдать ресурс». **Xvalue** (expiring value) — «умирающее» lvalue, например результат `std::move(x)`. Keyword `&&` в **типе параметра** связан с привязкой к rvalue; полная теория value category — в томах про move и перегрузки.

Практический вывод: после `take(std::move(obj))` снаружи `obj` в valid-but-unspecified state — не рассчитывай на содержимое без reassignment.

Именованная rvalue-ссылка внутри функции — всё ещё **lvalue** для правил перегрузки. Поэтому `std::vector<std::string> v;` и `v.push_back(std::move(s));` внутри `take` — явный move; голое `push_back(s)` скопирует, если тип параметра `string` по значению. Это не «баг `&&`», а правило языка.

## Параметры: `T&`, `const T&`, `T&&`, `T`

По значению **`T`** — копия или move при передаче rvalue; callee может портить копию freely. **`const T&`** — избегаем копии для lvalue и bind к temporary. **`T&&`** — sink для rvalue. **`T&`** — out-parameter или «гарантированно существующий» in-out; нельзя передать temporary.

Для маленького **`int`** разница в стоимости мала; для **`std::string`** и **`vector<T>`** сигнатура — часть документации. В заголовках STL увидишь перегрузки `push_back(T&&)` и `push_back(const T&)` — два keyword-контекста `&` и `&&` в одном API.

## **(C++23)** `std::optional<T&>`

Раньше «опциональная ссылка» делалась через указатель или `reference_wrapper`. **(C++23)** **`std::optional<T&>`** выражает «либо ссылка на живой объект, либо пусто» без syntactic null pointer. На Fedora 40+ проверь `g++ -std=c++23`; если стандарт в проекте C++17 — остаётся `T*` или `optional<reference_wrapper<T>>`. Keyword `optional` — не keyword языка, тип из `<optional>`; здесь важна связка с моделью ссылок.

## Указатель vs ссылка — выбор API

Указатель **nullable**, **reseat** (можно сменить адрес). Ссылка **не nullable** в нормальной модели, **не reseat**. «Может не быть объекта» — `T*` или **`std::optional<std::reference_wrapper<T>>`**; **(C++23)** в стандарт добавили **`std::optional<T&>`** — проверяй `-std=c++23` на твоём GCC.

| Ситуация | Частый выбор |
|----------|----------------|
| Обязательный аргумент, живёт дольше вызова | `T&` или `const T&` |
| Опционально / ошибка как null | `T*` или `std::optional` |
| Передача временного без копии | `T&&` + move внутри |
| Хранение «на кого указываю» с переназначением | `T*` или smart pointer |

## Keyword `this`

В **нестатическом** методе **`this`** — prvalue указателя на текущий объект:

```cpp
struct S {
    S* get_this() { return this; }
    const S* get_this() const { return this; }
};
```

В const-методе тип **`this`** — **`const S*`** (указатель на const объект): нельзя вызвать не-const методы через `this->`. Переназначить `this` нельзя — это не обычная переменная. Лямбда с `[this]` захватывает указатель; если объект уничтожен, вызов — UB — помни при async и потоках.

## Указатель на член

**Pointer to member** — отдельная категория:

```cpp
struct S { int x; };
int S::* pm = &S::x;
S obj;
obj.*pm = 10;
```

Операторы `.*` и `->*` — punctuators, не keywords. Сценарий редкий в прикладном коде, но встречается в низкоуровневых таблицах и биндингах.

## Жизненный цикл и контейнеры

Классическая ошибка: сохранить **`int*`** на элемент **`vector<T>`**, затем **`push_back`** вызвал reallocation — указатель dangling. Ссылка на элемент ведёт себя так же, если контейнер invalidates references. Для стабильных адресов — `list`, индексы, или не держать сырой указатель дольше, чем гарантирована стабильность.

С **`std::thread`** передача по ссылке `[&]` на локальную переменную `main`, пока поток ещё крутится после выхода из блока — классический UB. Передача по значению или join до уничтожения захваченного — из главы multithread, здесь — типовая причина: ссылка не продлевает жизнь.

## const и указатели — напоминание из главы 4

**`const T*`** — данные не меняем через указатель; **`T* const`** — адрес указателя фиксирован. В сигнатурах `void read(const int* p)` vs `void set(int* const p)` путаница ломает контракт. Читай справа налево.

## Проверка на Fedora

Минимальный файл с dangling reference часто **не** ловится компилятором:

```cpp
const int& bad() { int x = 0; return x; }
```

С `-Wall` Clang может предупредить (return stack address). Ссылки на временные в return без правил lifetime — тестируй с **AddressSanitizer**: `g++ -fsanitize=address -g`.

## Захват в лямбдах: `[&]`, `[=]`, `[this]`

**`[&]`** захватывает ссылки на автоматические переменные из окружающей области — lifetime лямбды не продлевает lifetime переменных. Запуск **`std::thread`** с `[&] { use(local); }` и выход из функции до **`join`** — тот же dangling, что у **`int&`**.

**`[this]`** захватывает указатель на объект; безопасно, пока объект жив. В const-методе лямбда всё равно может вызывать не-const методы, если ты так написал тело — const-ность метода на захват не распространяется автоматически.

**`[=]`** копирует захват; для больших структур дорого. **(C++14)** generalized capture **`[ptr = std::move(p)]`** — move внутрь closure. Ссылки и указатели в упражнении кузницы — практика из multithread, здесь — типовая основа.

## Связь с умными указателями (не keywords)

**`std::unique_ptr<T>`** и **`shared_ptr`** — типы из библиотеки, не keywords. Модель владения: unique — move-only; shared — счётчик. Сырой **`T*`** из **`.get()`** не продлевает lifetime объекта, на который указывает smart pointer — не сохраняй **`T*`** дольше, чем жив **`unique_ptr`**. Keyword **`nullptr`** с **`reset()`** и сравнениями — единый null для pointer type.

## Типичные ошибки

**`int& f() { int x = 0; return x; }`** — dangling reference. **`T&&`** в шаблоне без **`forward`** — лишние копии, «perfect forwarding» не работает. Хранить **`T*`** на элемент **`vector<T>`** через reallocation. Путать **`const T*`** и **`T* const`**. Думать, что **`this`** — ссылка: это указатель, разыменование не нужно для доступа к полям (`this->x` эквивалентно `x`).

## Краткое резюме

Указатель nullable и reseat; **`nullptr`** **(C++11)** — keyword для null. **Lvalue ref `&`** — alias; **`const T&`** — bind к temporary с осторожностью к lifetime. **Rvalue ref `&&`** **(C++11)** — move и forwarding; внутри функции параметр — lvalue. **`this`** — указатель на текущий объект; в const-методе **`const T*`**. `&`, `*`, `&&` в типах и в выражениях — разный синтаксис.
