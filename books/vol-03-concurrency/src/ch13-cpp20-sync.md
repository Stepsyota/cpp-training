# Глава 13. Синхронизация C++20: jthread, latch, barrier, semaphore

## Зачем эта тема

Базовый трек репозитория зафиксирован на **C++17**: `std::thread`, `mutex`, `condition_variable`, `atomic`. Этого достаточно, чтобы собрать пул, очередь и parallel map. **C++20** добавляет примитивы, которые **снимают частые боли** — забытый `join`, остановка воркера без «ядовитого» флага, одноразовое «все на старте», циклические барьеры, семафоры. Том 3 помечает их явно **(C++20)**, чтобы не смешивать с обязательной базой упражнений.

Эта глава — **обзор**, не замена глав 1–11: happens-before, mutex и cv остаются фундаментом. Новые типы **упрощают выражение** паттернов, но **не отменяют** data race, если ты по-прежнему пишешь в общий `int` без синхронизации.

## `std::jthread` и `std::stop_token` **(C++20)**

Класс **`std::jthread`** (joining thread — поток с автоматическим join) ведёт себя как `std::thread`, но **в деструкторе** вызывает **`request_stop()`** (если поддерживается) и **`join()`**, если поток joinable — то есть типичный «забыл join → `std::terminate`» для `std::thread` (глава 1) снимается **при нормальном уничтожении** `jthread`. Это не отмена magic: уничтожение объекта, пока поток ещё держит ссылки на уже мёртвые данные, по-прежнему UB; `jthread` не продлевает lifetime захваченных `[&]`.

**`std::stop_token`**, **`std::stop_source`**, **`std::stop_callback`** **(C++20)** образуют кооперативную отмену:

- **`stop_source`** — кто-то «владеет» правом попросить остановку (часто главный поток или RAII-объект).
- **`stop_token`** — лёгкая копируемая ручка, которую передают в воркер; **`stop_requested()`** проверяет флаг.
- Воркер периодически смотрит token в цикле и выходит **сам**, без `pthread_kill`.

`jthread` при создании может передать в callable **`stop_token`** как первый аргумент, если сигнатура это допускает — удобно для «кузнеца», который крутится, пока не попросили остановиться. Это **мягче**, чем только `stopped` под mutex в пуле, но **не заменяет** очередь задач: stop говорит «закончить цикл», а не «дождись idle и flush jobs».

Сравнение с главой 10: флаг **`stopped`** в пуле под **`mutex`** + **`notify_all`** — C++17-идиома; **`stop_token`** — стандартизованный канал отмены **без** обязательного mutex для **самого флага** (реализация атомарна внутри). Очередь работ и **`busy`** всё равно требуют твоей синхронизации.

На Fedora для учебных экспериментов: **`g++ -std=c++20 -pthread`**. В `multithread/` без запроса не меняем стандарт задач.

## `std::latch` **(C++20)**

**`std::latch`** — одноразовый **down-counter** с блокировкой:

- Конструктор: «сколько **`count_down`** / **`arrive`** нужно, чтобы барьер открылся».
- **`count_down(n)`** / **`arrive(n)`** уменьшают счётчик; когда доходит до нуля, все **`wait()`** разблокируются.
- **Не сбрасывается** — для повторяющихся фаз используют **`barrier`**.

Сценарий: **N** воркеров должны закончить фазу «загрузка данных», прежде чем главный продолжит. Каждый по завершении вызывает **`arrive_and_wait()`** (или `count_down` + `wait` у главного). Проще, чем вручную крутить mutex + cv + «сколько уже пришло», если нужен **один** рубеж.

Не путать с **`std::counting_semaphore`**: latch — «все пришли один раз»; semaphore — «есть N слотов».

## `std::barrier` **(C++20)**

**`std::barrier`** — **многоразовый** синхронизационный барьер на **фиксированное** число участников:

- Участник вызывает **`arrive_and_wait()`**; когда **все** текущей «фазы» пришли, выполняется опциональный **`completion function`** (например, агрегировать локальные частичные суммы в один буфер), затем барьер **сбрасыается** для следующей фазы.

Подходит для итерационных parallel алгоритмов «шаг — sync — шаг» (например, несколько раундов локальной обработки с глобальным reduce между раундами). В прикладном серверном коде встречается реже, чем latch или cv, но на собеседовании отличают **one-shot latch** vs **reusable barrier**.

## `std::counting_semaphore` **(C++20)**

**`std::counting_semaphore<LeastMax>`** — классический **семафор** со счётчиком **permits (разрешений)**:

- **`release(n)`** увеличивает число разрешений, будит ждущих.
- **`acquire()`** / **`try_acquire`** забирают разрешение; если ноль — блокировка (или неблокирующий false).

Модель: **N** одновременных доступов к ресурсу (соединения к БД, слоты в пуле **не задач**, а **ограничителя параллелизма**). Bounded queue можно **мысленно** связать с «ёмкостью», но queue в C++17 обычно cv + mutex; semaphore **(C++20)** иногда **заменяет** пару «счётчик + cv» для **только** slot counting, если очередь элементов отдельно.

**`std::binary_semaphore`** **(C++20)** — typedef с LeastMax 1; близок к mutex, но **не** владелец-recursive и семантика acquire/release другая (можно передавать «слот» между потоками без «lock owner»). Для взаимного исключения по-прежнему чаще **`mutex`**.

## `jthread` и деструктор: что реально меняется

`std::jthread` **(C++20)** снимает класс terminate от **забытого join** при нормальном уничтожении объекта jthread — но **не** отменяет правила lifetime захватов и **не** drain'ит очередь пула автоматически. Деструктор jthread вызывает `request_stop()` и join — worker должен **сам** выйти из цикла, прочитав `stop_token`, иначе join всё равно ждёт.

Миграция `06_thread_pool` на jthread **без** пересмотра протокола stopped/queue — косметика; миграция **с** stop_token для цикла кузнеца + прежний mutex для jobs — осмысленный эксперимент на `-std=c++20`.

## `latch` vs barrier: сценарии из жизни

**Latch:** «все N worker'ов загрузили shard — только тогда main стартует reduce». **Barrier:** «каждый раунд итераций — sync — следующий раунд» в numeric kernel. Ни то ни другое не заменяет **cv** для «очередь то пуста, то полна» — разные абстракции.

## Semaphore и bounded queue (концептуально)

`counting_semaphore` **(C++20)** можно представить как «число свободных слотов» без хранения элементов — сами элементы всё равно в `queue` под mutex. Смешивать «sem для cap» и «deque без lock» — гонка. Для C++17 курса достаточно `not_full`/`not_empty`.

## `atomic::wait` / `notify` **(C++20)** — одна строка

Появилась блокировка потока на atomic без mutex; протокол ordering согласован с моделью памяти. Не путать с `condition_variable` для сложных инвариантов deque. В репозитории на C++17 не требуется.

## Типичные заблуждения

«**jthread** = безопасный `[&]`» — **нет**, lifetime захватов твоя ответственность. «**stop** убивает поток ОС» — **кооперативный** выход из цикла. «**barrier** и **latch** взаимозаменяемы» — latch **не** перезапускается. «Семафор **всегда** быстрее mutex» — другая модель; для простого lock — mutex проще. «C++20 **заменяет** condition_variable» — cv остаётся для **условий** «очередь не пуста».


## Глубже: migrating stop_token в worker loop

Псевдопротокол **(C++20)**: `while (!stop_token.stop_requested()) { wait for work or stop; ... }` — stop проверяют **и** в predicate cv (через stopped flag), и через token для быстрого exit без лишних notify. Дублирование флагов — design choice; один источник truth проще для учебного C++17.

## `std::barrier` и completion step

Completion function выполняется **одним** потоком «от имени» барьера после того, как все arrive — удобно для агрегации partial results между фазами numeric code.

## `stop_source` и владение отменой

Один `stop_source` на «сессию» работы: главный или RAII-объект пула. Копии `stop_token` раздают worker'ам. `request_stop()` идempotent по смыслу «попросить остановку»; worker проверяет token в цикле **и** должен выйти из blocking wait — часто комбинируют с `stopped` + `notify_all`, иначе worker спит в cv, не видя stop.

## `latch`: типичные числа

`std::latch{N}`: ровно N участников должны `count_down`/`arrive`, прежде чем waiters проснутся. Off-by-one здесь — классический баг «main ждёт вечно». В тестах latch часто N = число worker + main.

## `barrier`: фазы и reset

После completion function барьер **сбрасывается** для следующей фазы; число участников фиксировано при создании. Если один поток умер — барьер **никогда** не откроется; jthread/stop не спасает без дизайна.

## `counting_semaphore`: permits

Initial count = число слотов. Producer `release` (вернуть слот), consumer `acquire` (занять). Не путать с «ёмкость очереди»: семафор не хранит элементы, только **право** пройти.

## Сравнение с C++17 baseline репозитория

| Остановить цикл worker | `stopped` + mutex + cv | + `stop_token` |
| «Все N готовы» | mutex + counter + cv | `latch` |
| Ограничить параллелизм N | mutex + counter | `counting_semaphore` |

## Краткое резюме

**(C++20)** добавляет **`jthread`** (join в деструкторе), **`stop_token`** для кооперативной отмены, **`latch`** (один раз «все пришли»), **`barrier`** (фазы с reset), **`counting_semaphore`** (N слотов). База упражнений остаётся **C++17**; новые примитивы дополняют, а не отменяют mutex, cv и atomics. Пул и bounded queue из глав 10–11 можно **перевести** на stop/semaphore **осознанно**, не «ради моды».
