# Глава 1. Что где лежит

## Зачем эта глава

Репозиторий `training` — не одна «книга в PDF», а **несколько треков**: практика с автопроверкой, конспекты в Markdown и **отдельные EPUB-тома**. Без карты легко открыть чат, ждать теорию про mutex, а нужный текст уже лежит в томе 3 — или наоборот, читать книгу про sanitizer, когда пора просто собрать флаг в CMake.

Здесь — схема «что для чего», без углубления в синтаксис C++.

## Два слоя обучения

**Практика (репозиторий).** Ты меняешь код в заданных файлах, собираешь CMake (или `g++` в папке задачи), гоняешь тесты. Успех = зелёный бинарник / `./check.sh`.

**Теория (тома в `books/`).** Длинные, вычитанные главы под Kindle: можно вернуться к memory order или к флагам компилятора через полгода. Тома **не подменяют** тесты и **не содержат** готовых решений упражнений (если явно не оговорено отдельно).

Чат с AI-репетитором — **третий** канал: подсказки по текущей задаче, разбор твоего кода, ответы на вопросы по главе (см. главу 3).

## Серия томов (план)

Порядок **написания и чтения книги** совпадает с номерами:

| Том | Папка | О чём |
|-----|--------|--------|
| 0 | `books/vol-00-guide` | этот EPUB |
| 1 | `vol-01-keywords` | ключевые слова C++, стандарты 17/20/23 |
| 2 | `vol-02-lambdas` | лямбды, захват, C++17 и C++20 |
| 3 | `vol-03-concurrency` | потоки, mutex, cv, atomics, memory order |
| 4 | `vol-04-async` | async/future, executors, coroutines |
| 5 | `vol-05-toolchain-flags` | GCC/Clang, флаги, MSVC — отличия |
| 6 | `vol-06-debugging` | GDB, cgdb, IDE |
| 7 | `vol-07-sanitizers` | ASan, UBSan, TSan |
| 8 | `vol-08-oop` | ООП, SOLID, проектирование на C++ |

Актуальный статус томов — в файле `books/README.md` в корне клона репозитория.

Глубина всей серии согласована как **очень подробная**: и «перечитать правило», и «как это стыкуется с практикой», и плотные § (в т.ч. happens-before, coroutines, санитайзеры).

## Трек `multithread/`

Папка `multithread/` — **многопоточность руками**.

- `THEORY.md` — живой конспект из прошлых сессий (потоки, mutex, async, cv, atomics, move в очередях). Его смысл **не исчезает**: том 3 развернёт те же идеи в формате учебника.
- `beginner/01`…`05` — короткие задачи (`task.cpp`).
- `advanced/01`…`03` — крупные модули (пул, bounded queue, parallel map).
- `solutions/` — эталоны **после** своей попытки.
- `check.sh` — прогон всех восьми.

Типичный цикл:

```bash
cd multithread
cmake -S . -B build
cmake --build build --target 06_thread_pool
./build/06_thread_pool
```

Стандарт здесь: **C++17**, `-pthread`. Это база репозитория; в томах 1–4 фичи 20/23 идут с пометками.

**Как стыкуется с книгой:** прошёл `04_elevator` — в томе 3 найдёшь полную картину `condition_variable` и lost wakeup; прошёл `06_thread_pool` — там же разбор паттерна пула без спойлера твоего кода.

## Трек `cicd/`

Папка `cicd/` — **GitLab CI/CD**, Docker, артефакты, manual deploy. Теория в `cicd/THEORY.md`; упражнения `beginner/01`…`06`; учебный продукт `workshop/` (forge-cli).

Книга перекликается с треком в **томе 5** (сборка) и частично в **томе 7** (санитайзеры в pipeline), но `.gitlab-ci.yml` и `check.sh` для cicd ты по-прежнему пишешь сам в упражнениях — тома не подменяют CI.

## Корень репозитория

- `AGENTS.md` — договорённости для агентов (язык, что не спойлерить, как учить). Полезно прочитать **тебе**, если настраиваешь новый чат.
- `.vscode/` — локальные настройки редактора (например, отключение inline-подсказок — осознанный выбор).

## Куда смотреть в типичных ситуациях

| Ситуация | Куда идти |
|----------|-----------|
| Застрял в `task.cpp`, нужна идея, не код | Чат-репетитор + README задачи |
| Хочу системно memory order | Том 3 + `multithread/THEORY.md` |
| Настроить `-fsanitize=address` | Том 7; для быстрого старта — README упражнения / репетитор |
| Забыл, что такое `co_await` | Том 4 |
| Полный список слов `mutable`, `volatile` | Том 1 |
| SOLID и иерархии классов | Том 8 |

## Типичные заблуждения

- **«Всё должно быть в одном PDF»** — серия из EPUB удобнее на Kindle: том 6 не раздувает том 3.
- **«Зелёный тест = я всё понял»** — тесты не покрывают все края (например, нарезка диапазона с остатком в `08`). Книга как раз про такие дыры.
- **«Репетитор заменяет THEORY.md»** — репетитор контекстен чату; тома и `THEORY.md` — долговременная память.

## В каком порядке читать тома

Номера томов — не жёсткий экзамен, но **логика накопления** есть.

**Том 1 (keywords)** даёт словарь: `mutable`, `constexpr`, ссылки, `noexcept`. Без него в томе 2 лямбды читаются как «магия скобок», в томе 3 — путаются `memory_order` и «просто atomic».

**Том 2 (lambdas)** стыкуется с пулом и STL: захват `[&]` vs `[this]`, `std::function`, потоки в ch09. Имеет смысл после тома 1 или параллельно с `multithread/beginner`, когда уже видел лямбду в `std::thread`.

**Том 3 (concurrency)** — теоретический брат `multithread/`. Практику 01–08 можно вести раньше; книгу тома 3 удобно читать **после** `04_elevator` и **во время** `06`–`08`, когда вопросы про `notify`, очередь и нарезку уже живые.

**Том 4 (async)** опирается на `03_oracle` и главу 6 `THEORY.md`: `future`, `promise`, дальше — coroutines как отдельная ветка (C++20 помечено в тексте).

**Том 5 → 6 → 7** — цепочка «собрать с флагами → отладить → поймать гонку санитайзером». Если ASan ругается, а ты не умеешь открыть gdb — сначала том 6, потом снова том 7.

**Том 8 (ООП/SOLID)** не требует многопоточности, но хорошо ложится **после** тома 1: виртуальные деструкторы и Rule of Five перекликаются с RAII в пуле и очереди.

Кратко: **0 → 1 → (2 ∥ multithread) → 3**; **4** когда интересен async; **5–7** когда отлаживаешь сборку; **8** когда хочешь структуру классов, а не только потоки.

## Недельный ритм (пример)

Не обязательная программа — шаблон, чтобы книга не пылилась:

- **2–3 вечера:** одна глава EPUB + 5 вопросов в конце (устно или в чат репетитору).
- **2–3 вечера:** одна папка `multithread/...` или прогон `./check.sh`.
- **Раз в неделю:** пересобрать EPUB тома, который правишь (`mdbook build`), если читаешь свежую версию из репо.

Смешивать «читать том 3» и «писать `07_bounded_queue`» нормально: книга даёт инварианты, код проверяет, что ты их удержал.

## Файлы, которые не трогаешь в упражнении

В `multithread/beginner/01_rocket_launch` ты правишь только то, что README называет «ты пишешь» — обычно `task.cpp`. Не трогаешь без нужды:

- `test.cpp` — спецификация;
- `CMakeLists.txt` в корне трека — общая сборка;
- `check.sh` — агрегатор;
- чужие `advanced/*/factory.cpp` и подобные «цехи».

В `books/` при чтении ничего собирать не обязательно, кроме желания свежего EPUB.

## Краткое резюме

- Практика: `multithread/`, `cicd/`.
- Долгая теория: `books/vol-XX-...` → EPUB.
- Том 0 — карта; тома 1–8 — темы по согласованному плану; **8 — ООП и SOLID**.
- Стандарт упражнений: C++17; книга явно помечает 20/23.
