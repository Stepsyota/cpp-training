# Глава 3. Репетитор и обсуждение глав

## Зачем эта глава

EPUB и `THEORY.md` не отвечают на вопрос «а почему **мой** `wait` завис?». Для этого — **отдельный чат-репетитор** (в Cursor или другой среде), с правилами из `AGENTS.md`. Эта глава фиксирует, **что спрашивать где**, и как ссылаться на главу книги, чтобы не начинать с нуля.

## Три канала — три роли

| Канал | Роль | Хороший запрос |
|-------|------|----------------|
| **Том EPUB** | Выучить и перечитать тему | «Объясни ещё раз acquire/release» |
| **`multithread/THEORY.md`** | Быстрый конспект по пройденному | «Где мы писали про lost wakeup?» |
| **Репетитор** | Твой код, текущая задача, квиз | «Проверь `thread_pool.cpp`, не подсказывай CAS» |

Репетитор **не обязан** быть тем же агентом, что пишет тома. Агент книги (`cpp-training`, тома) **не** меняет твои `task.cpp` и **не** коммитит без просьбы.

## Как учиться на упражнениях (договорённость)

Пока ты **пишешь** задачу, репетитор:

- называет дыру, аналогию, что проверить;
- **не** вставляет готовый цикл, `wait` или CAS.

Когда просишь **«проверь» / «оцени»** — можно разбирать код, гонять тесты, хвалить конкретное, показывать остаток.

Эталоны в `solutions/` — только **после** попытки. Тома книги — не замена `solutions/`.

## Идентификаторы глав

В конце каждой главы EPUB есть блок:

```text
Том: N · Глава: ch0K · Файл: ch0K-....md
```

В новом сообщении репетитору копируй эту строку и формулируй вопрос. Пример:

> Том 3 · ch06 · `ch06-memory-orders.md` — не понял, зачем relaxed для счётчика статистики, если результат никто не читает для синхронизации.

Так чат понимает, что теория уже в книге, и не разжёвывает с нуля — unless попросишь.

Для **тома 0** сейчас:

- `ch01` — карта репозитория;
- `ch02` — mdBook и Kindle;
- `ch03` — этот текст.

## Отдельные чаты (рекомендация)

Имеет смысл **не смешивать** в одной ветке:

1. **Практика** — «делаю 06_thread_pool».
2. **Теория книги** — «читаю том 1, вопросы по `volatile`».
3. **Автор тома** — правки оглавления и манускрипта (роль «учебник»).

Смешивать можно, но контекст смешивается: репетитор начнёт править `SUMMARY.md`, а автор книги — твой `bounded_queue.hpp`.

## Что положить в первое сообщение репетитору

Минимум:

- какая **папка** (`multithread/advanced/01_thread_pool`);
- что уже сделано и что падает (тест, ASan, gdb backtrace);
- ограничение: «не давай готовый код» или «можно критиковать жёстко».

Для теории по книге:

- строка **Том / глава / файл**;
- цитата 2–3 предложения из EPUB, которое спорно;
- твоя гипотеза («кажется, seq_cst всегда нужен»).

## AI в редакторе

В `AGENTS.md` зафиксировано: inline-подсказки (Tab) ты отключал, чтобы думать сам. Репетитор в чате — осознанный выбор; том на Kindle — без автодополнения кода. Это согласованные режимы, не противоречие.

## Примеры хороших сообщений

**Практика, без спойлера:**

> `multithread/advanced/02_bounded_queue` — `push` блокируется навсегда при `cap_=2`. Подскажи, какой предикат у `not_full`, без готового `wait`. Том 3 · ch09 если нужно.

**Проверка кода:**

> Проверь мой `thread_pool.hpp`: тесты зелёные, но `wait_idle` иногда не возвращается. Можно критиковать жёстко, эталон не открывал.

**Только книга:**

> Том 7 · ch04 · `ch04-asan-reports.md` — не понял, почему stack trace обрывается на `libc.so`. Объясни на примере одного кадра.

**Смешанный (осторожно):**

> Читаю том 8 ch11 (LSP) и рефакторю свой учебный класс `Drawable` — ок ли заменить базовый класс на `concept` в C++20? Упражнение multithread не трогаю.

## Эскалация: когда менять канал

| Симптом | Действие |
|---------|----------|
| Один и тот же вопрос третий раз в чате | Открыть главу EPUB + `THEORY.md`; в чат — только «что не сходится с текстом» |
| Нужен эталон | Сначала своя попытка + тест; потом `solutions/` или «покажи только diff идеи» |
| Падает CI / Docker | Трек `cicd/`, не том 3 |
| Хочешь править текст книги | Отдельный чат «автор тома», не репетитор по `task.cpp` |

## Типичные ошибки

- **Спрашивать репетитора «напиши том 3»** в чате практики — лучше агент/ветка «учебник».
- **Ждать спойлер решения** в фразе «подтолкни» — нормально уточнить: «без кода, только инвариант очереди».
- **Не указывать стандарт** — если смешиваешь C++17 упражнение и C++20 coroutine из тома 4, напиши явно, о чём речь.
- **Копировать полстраницы кода без вопроса** — лучше: «строки 40–55: почему `unlock` до `job()`?»

## Краткое резюме

- Книга = долгая память; репетитор = твой код и текущий вопрос.
- В конце главы — id для чата.
- Упражнения: подталкивание без готовых решений; проверка — по запросу.
- Разделяй чаты практики, чтения и авторства томов.
