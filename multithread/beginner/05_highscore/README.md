# 05. Рекорд автомата

Несколько игроков одновременно пытаются записать свой счёт в общий
`highscore`. Это `std::atomic<int>` — одиночные `load`/`store` безопасны,
но пара «прочитал → решил → записал» уже нет.

Допиши `consider_score` в `task.cpp`.

## Что должно получиться

- счёт меньше текущего рекорда его не меняет;
- после кучи параллельных обновлений в `highscore` лежит **настоящий**
  максимум, а не случайное меньшее число.

## Подсказка

Цикл с `compare_exchange_weak` (или `_strong`):

1. читаешь текущее значение;
2. если `score` не больше — выходишь;
3. иначе пытаешься атомарно заменить старое на `score`;
4. если не вышло (кто-то успел раньше) — `current` уже обновлён, повторяешь.

Мьютекс здесь ставить не нужно: задача как раз про lock-free обновление.

## Проверка

```bash
cmake --build build --target 05_highscore
./build/05_highscore
```
